# WARP.md

This file provides guidance to WARP (warp.dev) when working with code in this repository.

## Project overview

**moose** is an R package for managing dichotomous keys (bifurcating decision
trees used in taxonomic identification) and phylogenies with known mutations
such as PhyloTree. Exploratory Python and R work around it lives in
`analysis/` and is not part of the package.

## Layout

- `R/` - package source
  - `moose.R` - R6 classes `moose` (a key: lead table `$leads`, paths `$df`, `$meta`, `$taxa`) and `rawhtml`
  - `import.R` - `importFishbase()` / `parseFishbase()` (FishBase keys), `keyPaths()`, taxonomy resolution
  - `export.R` - `exportWizard()`: self-contained, mobile-friendly HTML key with a live map
  - `keys.R` - `keyFromLeads()`, `keyFromRpart()`, example keys `sharkKey()`, `arachnidaKey()`, `vibrioKey()`, and the `arachnida` / `vibrio` dataset docs
  - `phylotree.R` - `phylotree17` / `phylotree17_mutations` docs and `phylotreeKey()`
  - `generate.R` - `generateTree()` (rpart / randomForest / gbm from a feature matrix)
- `inst/wizard/` - wizard CSS and JavaScript, inlined into every exported page
- `data/` - `phylotree17`, `phylotree17_mutations` (PhyloTree Build 17 via Haplogrep 3), `arachnida` (lead table), `vibrio` (consensus matrix)
- `data-raw/` - how each dataset is built; `phylotree17/verify_against_github.R` checks the PhyloTree data against GitHub
- `inst/extdata/fishbase/` - saved FishBase pages for key 1 (used by `sharkKey()` and the tests)
- `man/` - generated by roxygen2; do not edit by hand
- `tests/testthat/` - tests (offline except the live FishBase tests); `test-example-keys.R` runs every method on all four example keys
- `analysis/` - exploratory work (see `analysis/README.md`); excluded from the package build
- `references/` - copyrighted PDFs used by `analysis/`; git-ignored

## Development commands

```bash
Rscript -e 'devtools::document()'   # regenerate NAMESPACE and man/
Rscript -e 'devtools::test()'       # run tests (live FishBase tests skip when offline)
R CMD build . && R CMD check --as-cran moose_*.tar.gz

# PhyloTree data
sh data-raw/phylotree17/build.sh                  # rebuild from Haplogrep 3 (curl, python3, R)
Rscript data-raw/phylotree17/verify_against_github.R        # pinned release
Rscript data-raw/phylotree17/verify_against_github.R main   # latest on GitHub
```

Run `analysis/` scripts from inside their own folder; see `analysis/README.md`
for dependencies and how to re-create the Sparrow setup used for table
extraction.

## Key concepts

- Every key is a `moose` R6 object with fields `leads`, `df`, `meta`, `taxa`,
  `desc` and methods `print()`, `summary()`, `validate()`, `toDataTree()`,
  `toNewick()`; `exportWizard()` works on any of them.

- A key is a table of **leads**: `Statement` (couplet), `Choice`, `Character`,
  `Next` (next couplet, or `-` for a result) and `Taxon`; optional `Label`,
  `Image`, `ImageLink`, `TaxonUrl`. FishBase keys arrive in exactly this shape.
- Couplet numbering in printed keys: `1.` / `1'.` are the two leads of couplet 1;
  `2(1).` means couplet 2 is reached from couplet 1.
- PhyloTree mutations are in RSRS orientation; `!` is a back-mutation (it
  reverts the latest change at that position). `phylotreeKey()` turns each
  haplogroup with subclades into a step, plus a "none of these" choice for the
  paragroup (`H2a*`).
